Haplina Stream Pack Privacy Policy

This Privacy Policy explains in detail how Haplina Stream Pack accesses, uses, stores, retains, shares, and deletes information, including Google and YouTube user data obtained through OAuth 2.0 and the YouTube Data API.

Effective: 9 September 2026 Contact: David@c0degeek.dev

1. Application covered by this policy

This policy applies specifically to Haplina Stream Pack, a local desktop companion and streaming toolkit for OBS Studio. Haplina Stream Pack can provide overlays, alerts, controls, combined chat features, and optional integrations with third-party streaming services such as YouTube, Twitch, and StreamElements.

Haplina Stream Pack is an independent project and is not operated by Google, YouTube, Twitch, StreamElements, or OBS Studio.

2. Local-first design and data flow

Haplina Stream Pack is designed to run on the user's own computer. It does not require a Haplina-hosted user account or a Haplina cloud dashboard. Application settings and saved connection credentials used by the local application are kept on the user's device unless a feature explicitly states otherwise.

When a connected feature needs information from YouTube or another service, Haplina Stream Pack communicates directly with that service's official API endpoints from the user's computer. Haplina does not route those API requests through a separate Haplina-operated analytics, advertising, or profiling service.

3. Categories of information Haplina Stream Pack may access

The exact information available depends on the feature the user enables and the permissions the user grants. Haplina Stream Pack may access the following categories:

  • OAuth authorization data: access tokens, refresh tokens, token expiry information, and the scopes/permissions granted by the user.
  • YouTube channel data: channel identifiers and basic channel metadata needed to identify the authorized channel.
  • YouTube live-broadcast data: broadcast identifiers, live status, scheduled/current broadcast information, and the live-chat identifier required to connect chat to the correct broadcast.
  • YouTube live-chat data: chat message text and related message/author metadata returned by the YouTube API and needed to display or manage live chat.
  • User-initiated YouTube actions: information required to send a live-chat message or perform another supported chat or broadcast action when the user explicitly requests that action.
  • Other streaming-service data: when the user connects Twitch, StreamElements, or another supported service, Haplina may access channel identifiers, chat/event data, account or channel metadata, and authentication credentials necessary for that integration.
  • Local application settings: settings such as overlay preferences, selected themes, layout choices, connection state, and similar local configuration required to operate the application.

4. Google and YouTube OAuth

If a user chooses to connect a Google/YouTube account, Haplina Stream Pack uses Google's OAuth 2.0 authorization flow. The Google consent screen shows the permissions requested before access is granted. Haplina Stream Pack only receives access that the user approves.

Depending on the features enabled and the scopes granted, authorized YouTube access can be used to:

  • identify the user's authorized YouTube channel;
  • find the user's current or scheduled live broadcast;
  • obtain the live-chat identifier for that broadcast;
  • read live-chat messages and metadata for display in Haplina's local interface;
  • send a chat message when the user explicitly submits one;
  • perform a supported moderation or live-broadcast action only when the user explicitly invokes that feature and the granted permission allows it.

Haplina Stream Pack does not require access to Gmail, Google Drive, Google Contacts, Google Photos, or unrelated Google account data for its YouTube streaming features.

5. How Google and YouTube user data is used

Google and YouTube user data is used only to provide the Haplina Stream Pack feature that the user selected. Examples include locating the correct live broadcast, displaying live chat, reconnecting an authorized YouTube session, sending a chat message requested by the user, or carrying out another supported user-initiated YouTube action.

Haplina Stream Pack does not use Google user data for advertising, targeted marketing, credit scoring, sale to data brokers, unrelated profiling, or surveillance of users.

6. Google API Services User Data Policy and Limited Use

Haplina Stream Pack's use of information received from Google APIs is limited to the functionality disclosed in this Privacy Policy. Its use and transfer of Google user data is intended to comply with the Google API Services User Data Policy, including its Limited Use requirements.

7. OAuth tokens and authentication credentials

When a user authorizes YouTube access, OAuth access and refresh tokens may be stored locally on the user's computer so Haplina Stream Pack can reconnect without requiring a new Google sign-in every time. Tokens are used only to authenticate requests to the corresponding service on behalf of the user.

Authentication credentials are treated as sensitive local configuration. Haplina Stream Pack does not intentionally publish OAuth tokens, streaming-service tokens, or private connection credentials on this website or include a user's saved credentials in distributable public application files.

8. Storage

Application settings and saved credentials are stored on the user's own device. Haplina Stream Pack does not intentionally upload Google OAuth tokens or YouTube user data to a Haplina-operated cloud database.

Temporary live-stream information, such as current chat state, current broadcast state, or an in-memory alert queue, may be held only for as long as needed to operate the current session unless the application explicitly states that a particular item is saved.

9. Retention

Local configuration remains on the user's computer for as long as the user keeps it. Saved authentication credentials may remain locally until one of the following occurs:

  • the user disconnects or forgets the connection in Haplina Stream Pack;
  • the user removes Haplina Stream Pack's local data;
  • the user revokes the authorization at the connected service;
  • the token expires or is invalidated by the provider.

Haplina Stream Pack is not designed to build a permanent remote archive of YouTube live-chat messages or YouTube account activity.

10. Sharing and disclosure

Haplina Stream Pack does not sell Google or YouTube user data. It does not intentionally share Google or YouTube user data with advertisers, data brokers, or unrelated third parties.

Information is transmitted to the relevant third-party platform when necessary to carry out the user's requested feature. For example, a chat message submitted by the user is sent to YouTube so YouTube can publish it to the user's live chat.

Information may be disclosed if required by applicable law or a valid legal process, or when necessary to address fraud, abuse, or a security incident. Because Haplina Stream Pack is local-first, the project normally does not possess a central copy of the user's locally stored credentials or streaming data to disclose.

11. Analytics, advertising, and tracking

Haplina Stream Pack is not designed to monetize Google user data. The local application does not use YouTube user data to create advertising profiles or to serve targeted ads. The public policy website may be hosted by a third-party web-hosting provider, but visiting this website is separate from authorizing YouTube access inside Haplina Stream Pack.

12. Revoking Google/YouTube access

A user can stop Haplina Stream Pack from using a connected YouTube authorization by disconnecting or forgetting the YouTube connection in Haplina where that control is available, and by revoking the application's access from the user's Google Account permissions/security settings.

After Google authorization is revoked, Haplina Stream Pack cannot continue using that authorization unless the user grants access again. A locally cached token that has been revoked is no longer valid for Google API requests.

13. Deleting locally stored data

Users can remove locally stored Haplina Stream Pack configuration and credentials by using the application's disconnect/forget controls where available or by deleting the application's local data after stopping the application.

Deleting Haplina's local files removes Haplina's local copy of those settings and credentials. It does not delete information that YouTube, Twitch, StreamElements, or another third-party service independently stores under its own terms and privacy policy.

14. Security

Haplina Stream Pack is designed to keep its local control interface and credential files on the user's machine and to avoid exposing private credential data as public web content. Users should secure their operating-system account, avoid sharing credential files, keep the application and operating system updated, and revoke connected-service access if they believe credentials have been exposed.

No software, storage system, or network transmission method can guarantee absolute security.

15. Data from Twitch, StreamElements, and other services

When a user connects another supported streaming service, Haplina Stream Pack accesses only the information needed for the integration the user enabled. Such information can include account/channel identifiers, chat or event data, and authentication tokens. Those providers process data according to their own terms and privacy policies.

16. Children's privacy

Haplina Stream Pack is intended for users who are able to authorize the streaming services they use. It is not directed at children under 13 and is not designed to knowingly collect personal information from children through a Haplina-operated online service.

17. International use

Users may operate Haplina Stream Pack from different countries. Because the application is local-first, most Haplina-controlled data storage occurs on the user's own computer. Connected services such as Google/YouTube may process information in accordance with their own global infrastructure and privacy terms.

18. Changes to this policy

This policy may be updated when Haplina Stream Pack's features, permissions, data handling, or legal requirements change. Material changes will be reflected on this page by updating the effective date, and the published policy will be kept consistent with the application's actual Google-data practices.

19. Contact

Questions about privacy, Google/YouTube data handling, OAuth access, revocation, or deletion for Haplina Stream Pack can be sent to David@c0degeek.dev.
